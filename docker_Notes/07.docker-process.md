# Container Inspection & File Copy

## 1. Container Process Inspection: `docker top`

```bash
docker top <container_name_or_id>
```

- Shows the **running processes** inside a container from the **host's view**.
- It reads the host's process table and filters by the container's cgroup — it does not run `ps` inside the container.
- Works only on a **running** container.
- Useful to check if the main process (PID 1) is alive and what child processes exist.

```bash
docker top centos-app
```

Output columns: `UID`, `PID` (host PID), `PPID`, `C`, `STIME`, `TTY`, `TIME`, `CMD`.

**`docker top` vs `docker exec <c> ps aux`:**
- `docker top` = host-side view. Shows host PIDs.
- `docker exec ps aux` = in-container view. Shows container PIDs (from the container's PID namespace).

## 2. Listing and Starting Containers

```bash
# All containers (running + stopped)
docker ps -a

# Start a stopped container
docker start centos-app

# Confirm it is running
docker ps
docker top centos-app
```

## 3. Viewing Logs: `docker logs`

```bash
docker logs <container_name_or_id>

# Examples
docker logs httpd-app
docker logs -f httpd-app              # follow live
docker logs --tail 100 httpd-app      # last 100 lines
docker logs --since 10m httpd-app     # last 10 minutes
docker logs -t httpd-app              # with timestamps
```

- Shows **STDOUT and STDERR** of the container's main process (PID 1).
- Works on **running and stopped** containers (logs persist until the container is removed).
- Stored by default in `/var/lib/docker/containers/<id>/<id>-json.log` (json-file driver).
- If the app writes to files instead of stdout/stderr, `docker logs` will be empty. Fix the app to log to stdout/stderr (12-factor principle).

## 4. Copying Files: `docker cp`

### Syntax
```bash
docker cp <source> <destination>
```

- Source and destination can be a host path or `container:path`.
- Works on **running and stopped** containers.
- **You do not need to `docker exec` into the container to copy files.** `docker cp` works directly from the host.

### Host → Container
```bash
# Create a file on the host
echo "hello from host" > new2.txt

# Ensure the target directory exists inside the container
docker exec -it centos-app mkdir -p /folder

# Copy file to container
docker cp ./new2.txt centos-app:/folder/new2.txt

# Verify
docker exec -it centos-app ls -l /folder
```

Notes:
- The destination **directory must exist** inside the container. `docker cp` does not create parent directories.
- If you specify `centos-app:/folder/` (trailing slash), Docker copies into that folder keeping the filename.
- If you specify `centos-app:/folder/newname.txt`, Docker renames the file.

### Container → Host
```bash
# Copy a file out of the container
docker cp centos-app:/folder/new2.txt ./new2-from-container.txt

# Verify on the host
ls -l ./new2-from-container.txt
```

- The host destination directory **must exist**.
- If the destination is a directory, the file is copied inside it.
- If the destination is a path with a filename, the file is renamed.

### Copying Directories
```bash
docker cp ./mydir centos-app:/folder/          # host dir -> container
docker cp centos-app:/folder/mydir ./backup/   # container dir -> host
```

### Important Caveats
- `docker cp` uses `tar` under the hood and preserves **UID/GID** and permissions from the source.
- It does **not** follow symlinks inside the container by default — the symlink itself is copied.
- Files copied with `docker cp` go into the container's **writable layer**. They are **lost when the container is removed**.
- For persistent or shared data, use **volumes** or **bind mounts** — not `docker cp`.
- `docker cp` is not atomic. For live databases, stop writes or use a proper backup tool.

## 5. End-to-End Example

```bash
# 1. Start the container
docker start centos-app
docker ps

# 2. Check processes
docker top centos-app

# 3. Create a file on the host
echo "test data" > new2.txt

# 4. Create target dir in container
docker exec -it centos-app mkdir -p /folder

# 5. Copy host -> container
docker cp ./new2.txt centos-app:/folder/new2.txt

# 6. Verify inside the container
docker exec -it centos-app ls -l /folder

# 7. Copy container -> host
docker cp centos-app:/folder/new2.txt ./new2-copy.txt

# 8. Verify on the host
cat ./new2-copy.txt

# 9. Check logs
docker logs centos-app
```

## 6. Interview Points

### Common Questions & Answers
**Q: What does `docker top` show?**  
A: Running processes inside a container, from the host's process table. It requires the container to be running.

**Q: Difference between `docker top` and `docker exec <c> ps aux`?**  
A: `docker top` shows host PIDs from the host side. `docker exec ps aux` runs inside the container and shows PIDs from the container's PID namespace (main process is PID 1).

**Q: Does `docker logs` work on a stopped container?**  
A: Yes, logs persist in the container's json-file until the container is removed.

**Q: Why might `docker logs` be empty even though the app is running?**  
A: The app may be writing to files instead of stdout/stderr. Docker captures only STDOUT and STDERR of PID 1.

**Q: How do you copy a file from the host into a running container?**  
A: `docker cp ./file.txt <container>:/path/file.txt`. No need to exec into the container.

**Q: Does `docker cp` work on stopped containers?**  
A: Yes. It does not require the container to be running.

**Q: Where do files copied with `docker cp` go?**  
A: Into the container's writable layer. They are lost when the container is removed. Use volumes for persistence.

**Q: What happens if the destination directory does not exist in the container?**  
A: `docker cp` fails. The destination directory must exist; it does not create parent directories.

**Q: `docker cp` vs bind mount vs volume?**  
A: `docker cp` = one-time copy. Bind mount = host dir mounted into the container (live sync). Volume = Docker-managed persistent storage. Use volumes/bind mounts for ongoing data, `docker cp` for one-off transfers.

### Product-Based Scenarios
**Scenario: A container is running but `docker logs` shows nothing. How do you debug?**  
Check if the app writes to stdout/stderr. Check the logging driver in `docker info`. Inspect `docker inspect <c> --format '{{.HostConfig.LogConfig}}'`. If logs are file-based, `docker exec` and inspect the files.

**Scenario: You need to pull a config file out of a running container for debugging.**  
`docker cp <container>:/etc/app/config.yml ./config.yml`. No need to stop the container.

**Scenario: After copying a file into a container, you redeployed the container and the file is gone. Why?**  
The file was written to the writable layer, which is tied to that container. On recreation, it is lost. Use a bind mount or volume instead.

**Scenario: `docker cp` fails with "no such file or directory" for the destination.**  
Create the target directory first: `docker exec <c> mkdir -p /path`, then copy.

### Service-Based Scenarios
**Scenario: Client needs to update a config file in a running container. Recommended approach?**  
For short-term: `docker cp`, then restart the process. For long-term: use bind mount or volume, or rebuild the image with the config baked in. `docker cp` is not persistent.

**Scenario: Client asks how to view process details of a container.**  
`docker top <container>` for the host view, and `docker exec <container> ps aux` for the in-container view.

**Scenario: Client's app writes logs to a file inside the container and they can't see them with `docker logs`.**  
Explain stdout/stderr vs file logging. Recommend configuring the app to log to stdout/stderr, or use a bind mount for the log directory and read it from the host.

**Scenario: Client wants to back up a database running in a container.**  
Do not use `docker cp` on live DB files. Use the DB's native backup tool via `docker exec` (e.g., `mysqldump`), or stop the container and copy the volume.

## 7. Quick Takeaway
- `docker top <c>` = processes from host view. Container must be running.
- `docker start <c>` = start a stopped container. `docker ps -a` = list all.
- `docker logs <c>` = STDOUT/STDERR of PID 1. Works on running and stopped containers.
- `docker cp <src> <dst>` = copy files both ways. No exec needed. Works on running/stopped.
- Destination directory must exist. Files go to writable layer — lost on container removal.
- Use volumes or bind mounts for persistent data, not `docker cp`.
