# Docker CLI Commands & Command Structure

## 1. Docker Command Structure

```
docker <object> <subcommand> <options> <arguments>
or
docker run <options> <image> <command>
flow Options → Image → Command.
Example: docker run -it alpine:latest /bin/sh
Docker needs to know what to run first (the image), then what to execute inside it (the command).
```

- **object**: what you are working on — `image`, `container`, `network`, `volume`, `system`.
- **subcommand**: the action — `ls`, `run`, `rm`, `pull`, `inspect`.
- **options (flags)**: modify behavior — short flags start with `-` (`-d`, `-p`), long flags with `--` (`--name`, `--restart`).
- **arguments**: image name, container ID/name, file path, etc.

Two valid forms (both work):
```bash
# Modern (recommended, clearer)
docker container ls
docker image pull nginx

# Legacy shorthand
docker ps
docker pull nginx
```

### Three Sets of Commands
1. **Image commands** — manage images: `pull`, `push`, `build`, `images`, `rmi`, `tag`, `inspect`.
2. **Container commands** — manage containers: `run`, `ps`, `start`, `stop`, `rm`, `exec`, `logs`.
3. **System / service commands** — `system` (df, prune, info), `volume`, `network`, `service` (Swarm only).

## 2. Image Commands

```bash
# List local images
docker images
docker image ls

# Pull an image (no tag = latest)
docker pull nginx              # same as nginx:latest
docker pull nginx:1.25
docker pull ubuntu
docker pull alpine

# Remove an image
docker rmi nginx:latest
docker rmi <image_id>

# Remove unused images
docker image prune
```

**Note:** Without a tag, Docker uses `latest`. In production, always pin a version or digest — `latest` is mutable.

## 3. Container Commands

```bash
# List running containers
docker ps

# List all containers (running + stopped)
docker ps -a

# Only container IDs
docker ps -q

# All container IDs, including stopped (combined flags)
docker ps -qa        # same as -a -q

# Run a container in detached mode with port mapping
docker run -d -p 8000:80 nginx
docker run -d -p 8000:80 --name mycontainer nginx:1.25

# Stop and start
docker stop <container_id_or_name>
docker start <container_id_or_name>

# Remove a stopped container
docker rm <container_id_or_name>
```

**Port mapping:** `-p <host_port>:<container_port>` — traffic to host port 8000 goes to container port 80.

**Naming:** `--name mycontainer` assigns a readable name. Otherwise Docker generates a random one.

## 4. `docker run -it` vs `docker exec -it`

| Command | What it does |
|---|---|
| `docker run -it ubuntu` | Creates a **new** container from the image and gives an interactive shell. |
| `docker exec -it <container> bash` | Runs a shell in an **already running** container. Argument is a **container name or ID**, not an image. |

- `docker exec -it ubuntu` is **invalid** — `ubuntu` is an image, not a running container.
- `-i` keeps STDIN open, `-t` allocates a TTY. Together they give an interactive terminal.
- `docker exec` requires the container to be **running**.

## 5. `docker version`

Shows two sections:
- **Client** — CLI version, API version, Go version, Git commit, OS/Arch.
- **Server** (Docker Engine / daemon / Docker Desktop):
  - Engine version
  - containerd version
  - runc version (low-level OCI runtime)
  - OS/Arch, kernel version

**Why it matters:** CLI and server API versions can differ. A newer CLI may fail against an older daemon. Useful in support and incident debugging.

```bash
docker version
docker version --format '{{.Server.Version}}'
```

## 6. `docker info`

Shows detailed environment info:
- Client and server versions.
- **Storage driver** — manages image layers (e.g., `overlay2`).
- **Cgroup driver / version** — `systemd` / `cgroup v2`.
- Kernel version.
- Number of running/stopped containers and images.
- Docker root directory (`/var/lib/docker`).
- Logging driver.
- Registry mirrors, proxies, runtimes.

```bash
docker info
```

## 7. Logs

- Default logging driver on Linux: **`json-file`**.
- Logs stored on host at: `/var/lib/docker/containers/<container_id>/<container_id>-json.log`.
- View logs:
```bash
docker logs <container>
docker logs -f <container>       # follow
docker logs --tail 100 <container>
```
- Configure log rotation to avoid disk fill:
```bash
docker run --log-opt max-size=10m --log-opt max-file=3 nginx
```
- Other drivers: `syslog`, `journald`, `fluentd`, `awslogs`, `gelf`.

## 8. Interview Points

### Common Questions & Answers
**Q: Difference between `docker run -it ubuntu` and `docker exec -it ubuntu bash`?**  
A: `run` creates a new container from the image. `exec` runs a command in an existing running container. `exec` takes a container name/ID, not an image.

**Q: What does `docker ps -qa` do?**  
A: Lists **all** container IDs (running and stopped). `-q` = IDs only, `-a` = all.

**Q: What happens if you `docker pull nginx` without a tag?**  
A: Docker pulls `nginx:latest`. In production, avoid `latest` — pin a version or digest.

**Q: Difference between `docker rm` and `docker rmi`?**  
A: `docker rm` removes containers. `docker rmi` removes images. A running container must be stopped (or use `-f`) before removal.

**Q: Where are Docker logs stored by default?**  
A: In JSON files at `/var/lib/docker/containers/<id>/<id>-json.log`, using the `json-file` logging driver.

**Q: What does `docker info` show that `docker version` doesn't?**  
A: `version` shows only versions. `info` shows runtime environment: storage driver, cgroup driver, kernel, counts, root dir, logging driver.

**Q: What is the storage driver?**  
A: The component that manages how image layers and the container writable layer are stored on disk (e.g., `overlay2`).

### Product-Based Scenarios
**Scenario: Docker CLI says "client version 26, server version 20". Can this cause issues?**  
Check API version compatibility in `docker version`. Newer CLI features may fail on older daemons. Use the matching CLI or upgrade the daemon.

**Scenario: Host disk is full and Docker is the cause. How do you investigate?**  
`docker system df`, `docker info` for root dir, check `/var/lib/docker/containers/*/*-json.log` size. Run `docker system prune` and configure log rotation.

**Scenario: You need to enter a running container for debugging. What do you use?**  
`docker exec -it <container> sh` (or `bash`). Do not use `docker run` — that creates a new container.

**Scenario: Port 8000 on the host is already in use. What happens?**  
`docker run -p 8000:80` fails because the host port is bound. Change the host port: `-p 8080:80` or stop the conflicting process.

### Service-Based Scenarios
**Scenario: Client says container logs are missing. What do you check?**  
Verify the logging driver in `docker info`. If `json-file` is disabled or changed, logs go elsewhere. Check container config: `docker inspect <container> --format '{{.HostConfig.LogConfig}}'`.

**Scenario: Client wants to clean up stopped containers and unused images. Commands?**  
`docker container prune`, `docker image prune`, `docker system prune -a` (careful — removes all unused images).

**Scenario: Client asks the difference between `docker stop` and `docker rm`.**  
`stop` halts the process but keeps the container (can restart). `rm` deletes the container and its writable layer permanently.

**Scenario: Client needs the exact Docker and runtime versions for a support ticket.**  
Collect `docker version` (client, server, containerd, runc) and `docker info` (storage driver, kernel, cgroup driver).

## 9. Quick Takeaway
- Syntax: `docker <object> <subcommand> <options> <arguments>`.
- `docker ps -qa` = all container IDs. `-a` = all, `-q` = IDs only.
- `pull` without tag = `latest` (avoid in Prod).
- `run -it` creates a container. `exec -it` enters a running one.
- `rm` removes containers, `rmi` removes images.
- `docker version` = versions. `docker info` = environment details.
- Logs default to `json-file` at `/var/lib/docker/containers/`. Configure rotation.
