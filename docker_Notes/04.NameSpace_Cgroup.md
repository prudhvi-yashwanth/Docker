# Namespace & Cgroup

## 1. What Makes a Container?
- Containers are not a single Linux feature. They are built from two main kernel features:
  - **Namespaces** – control what a container can see (isolation).
  - **Cgroups** – control how much a container can use (resource limits).
- Docker, Podman, and containerd do not create these features. They use what the Linux kernel already provides.
- On Windows, similar concepts exist (Job Objects, Silos), but here we focus on Linux.

## 2. Namespaces – What You Can See

### Definition
- A namespace wraps global system resources so that processes inside it see their own isolated instance.
- Analogy: You are in a room in a house. You can only see and use things inside that room, even though the house has many rooms.

### What Namespaces Isolate
Each container gets its own view of:

| Namespace | Isolates | Example |
|---|---|---|
| PID | Process IDs | Container sees its own PID 1, not host processes |
| Mount (MNT) | Filesystem mounts | Container has its own root filesystem |
| Network (NET) | Network interfaces, IP, ports | Container has its own IP and port space |
| UTS | Hostname and domain name | Container can have its own hostname |
| IPC | Inter-process communication | Shared memory, semaphores isolated |
| User | User and group IDs | UID 0 inside can map to non-root outside |
| Cgroup | Cgroup view | Container sees its own cgroup hierarchy |
| Time | System clocks | (Newer) Boot time and monotonic clock offsets |

- Each container sees only its own processes, files, network, users, and hostname.
- The host can see all namespaces.

### Example
```bash
# List namespaces of a running container
docker inspect --format '{{.State.Pid}}' mycontainer
ls -l /proc/<pid>/ns/
```

## 3. Cgroups – How Much You Can Use

### Definition
- Cgroup = Control Group.
- It limits, accounts for, and isolates resource usage of a group of processes.
- Analogy: Your room has a limit on how much electricity and water you can use.

### What Cgroups Control
- CPU: shares, quota, period.
- Memory: limit, soft limit, swap.
- Block I/O: read/write bandwidth and IOPS.
- Devices: allow or deny access to devices.
- PIDs: maximum number of processes.
- Hugepages, RDMA, and more.

### Versions
- **cgroups v1**: multiple hierarchies, one per controller. Older, more complex.
- **cgroups v2**: single unified hierarchy. Modern default on most Linux distros. Better for containers.

### Example
```bash
# Run a container with memory and CPU limits
docker run -d --memory=512m --cpus=1 nginx

# Inspect cgroup limits inside the container
cat /sys/fs/cgroup/memory.max
cat /sys/fs/cgroup/cpu.max
```

## 4. How They Work Together

- **Namespaces** = isolation. They decide what the process can see.
- **Cgroups** = resource control. They decide how much the process can use.
- Together they create the container illusion: a process that thinks it has its own machine, but is actually sharing the host kernel.
- This is why containers are lightweight: no separate kernel, just kernel features.

## 5. Docker’s Role
- Docker does not implement namespaces or cgroups.
- Docker calls the Linux kernel APIs to create namespaces and set cgroup limits.
- The container runtime (runc, crun) does the low-level work.
- Docker adds: image format, registry, networking, volumes, CLI, and orchestration-friendly APIs.

## 6. Important Note on Isolation
- Namespaces and cgroups give process-level isolation, not hardware-level isolation like VMs.
- A kernel exploit can break out of a container.
- For stronger isolation, use:
  - Rootless containers.
  - User namespaces.
  - seccomp, AppArmor, SELinux.
  - Sandboxed runtimes like gVisor or Kata Containers.
  - VMs for untrusted workloads.

## 7. Interview Points

### Common Questions & Answers
**Q: What is a namespace?**  
A: A Linux kernel feature that isolates what a process can see, such as PIDs, network, mounts, and users.

**Q: What is a cgroup?**  
A: A Linux kernel feature that limits and accounts for resource usage like CPU, memory, and I/O for a group of processes.

**Q: How do namespaces and cgroups differ?**  
A: Namespaces control visibility (what you can see). Cgroups control resource usage (how much you can use).

**Q: Does Docker create namespaces and cgroups?**  
A: No. The Linux kernel provides them. Docker and other runtimes use them to build containers.

**Q: What are the main namespace types?**  
A: PID, mount, network, UTS, IPC, user, cgroup, and time.

**Q: What is the difference between cgroups v1 and v2?**  
A: v1 has separate hierarchies per controller. v2 has a single unified hierarchy. v2 is simpler and is the modern default.

**Q: Can you limit a container’s CPU and memory?**  
A: Yes, with cgroups. Example: `docker run --cpus=1 --memory=512m nginx`.

**Q: Is container isolation as strong as a VM?**  
A: No. Containers share the host kernel. VMs have separate kernels and stronger hardware-level isolation.

### Product-Based Company Scenarios
**Scenario: A container is using 100% CPU and affecting other services. How do you fix it?**  
Set a CPU limit with cgroups: `docker run --cpus=1`. Monitor with `docker stats`. Investigate the app for CPU spikes.

**Scenario: You need to run a container as non-root for security. What kernel feature helps?**  
User namespaces. They map root inside the container to a non-root user on the host. Use `--userns-remap` or rootless Docker/Podman.

**Scenario: A container needs its own hostname and network. What provides this?**  
UTS namespace for hostname, network namespace for network interfaces and IP.

**Scenario: You suspect a container can see host processes. How do you check?**  
Compare `ps aux` on the host with `docker exec <container> ps aux`. If it sees host processes, PID namespace is not working correctly.

### Service-Based Company Scenarios
**Scenario: Client wants to limit a container’s disk I/O. How?**  
Use cgroup blkio controller. Example: `docker run --device-read-bps /dev/sda:1mb nginx`.

**Scenario: Client asks why containers are lighter than VMs. What do you say?**  
Containers share the host kernel and use namespaces and cgroups for isolation and limits. VMs run a full guest OS with its own kernel.

**Scenario: Client needs to run untrusted code. What do you recommend?**  
Use VMs or sandboxed runtimes like gVisor or Kata Containers. Plain containers share the kernel and are not safe for untrusted code.

**Scenario: A container has a memory leak and gets OOM-killed. How do you debug?**  
Check `docker inspect` for `OOMKilled: true`. Review cgroup memory limits. Use `docker stats` and application profiling to find the leak.

## 8. Quick Takeaway
- Namespaces isolate what a container sees: PIDs, network, mounts, users, hostname.
- Cgroups limit what a container uses: CPU, memory, disk I/O, devices.
- Both are Linux kernel features. Docker uses them, does not create them.
- Together they make containers possible: lightweight, isolated, resource-controlled.
- They provide process-level isolation, not hardware-level. Harden for security.
